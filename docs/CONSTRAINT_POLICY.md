# 当前约束边界：程序检查可执行性，模型判断完整体验

日期：2026-10-27。本说明取代此前“晚间优先”“全程地点唯一”和固定密度阈值方案。

## 审计后的分类

| 项目 | 当前处理 | 理由 |
| --- | --- | --- |
| 活动、用餐、休息相互重叠；结束早于开始 | 硬校验 | 时间表本身不可执行 |
| 实际交通无法衔接、必要返程或住宿接驳缺失 | 硬校验 | 只看活动时段不重叠仍可能赶不上下一站 |
| 用户填写的每日窗口、抵离时间与缓冲、固定预约、锁定 | 硬校验 | 属于用户明确的时间承诺；纯抵离接驳按抵离边界处理早晚航班 |
| 必去地点、用户指定日期、明确排除项、已选酒店及入住日期 | 硬校验 | 用户明确的决策应得到保留 |
| 实际地点/交通/来源 ID、旅行日期、独立活动 ID、版本一致性 | 数据完整性校验 | 防止虚构地点、错误路段或覆盖错误版本；活动 ID 唯一不代表地点只能访问一次 |
| 有来源依据的营业窗口 | 硬校验 | 非演示数据需有 observed 营业证据与来源 URL；演示夹具只作为演示输入 |
| 未核实的营业时段 | 提醒与审核参考 | 不再把旧目录值或模型推测直接当成已确认的关闭条件 |
| 额外 10 分钟交通余量 | 提醒 | 不再将统一余量当作实际交通的一部分；用户填写的机场/车站缓冲仍是硬条件 |
| 活动数、长短搭配、是否重访、留白、节奏、多样性、室内外与天气取舍 | 整体审核 Agent 判断 | 不用固定数量、占用比例或某一时段配额取代旅行规划 |
| 模型请求/输出预算、总运行时间、地图调用数、限流 | 保留运行预算 | 控制费用、等待与高德 QPS，不是每日景点数配额 |

因此，必要约束不能仅理解为“活动不重叠、必去出现”两个布尔项：它们还包含真实转场、抵离/预约/住宿边界与数据真实性。其余体验取舍应尽量交给主 Agent 和审核 Agent。

## 已撤销或放松的限制

1. 新生成与修复统一返回整天 `daily_schedule.activities`，不再先写晚间、再从剩余候选补白天。`RepairScheduledDay` 仅用于读取旧分段响应，不再进入新提示词。
2. 删除模型时间表每天 12 项、白天 8 项、晚间 4 项、必去 12 项、预约 6 项等业务数量上限；用餐休息也没有固定条数配额。模型可决定少量长活动或多项短体验。演示规则规划撤销每日 3/4 项固定上限，仍有剩余候选/日期均衡的启发式；真实模型时间表直接进入时间核算，不受该演示启发式限制。
3. 取消全程 POI 不得重复的硬判断。同一地点可以日夜重访或跨日重访，由审核判断价值。各次访问产生独立活动 ID，交通按访问顺序匹配，不再取“第一个目的地 ID 相同的路段”。同一地点的多次固定预约也分别保留。
4. `time_intent`、模型给出的 earliest/latest 建议窗口和推荐理由不再触发固定时刻重排。删除 `19:00`、最短 30 分钟夜游、白天不能跨 19 点等程序政策；有实际交通冲突时仍可做有记录的物理时间修复，用户预约和锁定不移动。
5. 删除固定 45% 占用率、180 分钟留白和晚间门槛的运行时体验判断。审核不可用时明确提示未完成审核，不重新套固定阈值补一个“程序体验裁判”。旧检查代码集合仅用于清理旧预览记录。
6. 取消“少遗漏一晚就优先”的选版顺序，也不按审核问题条数机械扣分。先比较真实硬冲突，再参考审核对完整行程的 overall_score。分数是模型判断，可缺省、可有小数，不是事实或保存门槛；没有评分时不虚构密度惩罚，保留可行修改并显示其审核状态。
7. 完整具体时间表是实际安排的依据。冗余 place_ids/day_groups 与之不一致时从时间表派生，不因辅助索引拒绝合法安排；实际活动中的未知 ID 仍拒绝。`9:00:00` 与 `09:00` 等等价表示可规范化，但 `25:00` 等非法时间仍拒绝。
8. 允许休整日没有景点，交给模型解释和审核，而非强制每天至少一个点。休整日如需在两家已选酒店之间移动，或有抵离接驳，仍须有可行交通。
9. 页面不再按固定 19 点判定夜景理由未落实。只有整体审核明确指出相关时段/理由矛盾时才显示该提醒。

## 规划与审核流程

用户需求、目的地、候选、攻略报告和天气进入主 Agent。主 Agent 自由提出完整时间表；程序核算地点、交通、用户硬条件和数据完整性；独立审核比较整天安排与偏好，给出整体评分、具体问题和建议。主 Agent 在预算内重新组织完整行程，建议可以采纳，也可以解释有依据的取舍。

不会因为活动多就直接判拥挤，也不会因为活动少就直接判稀疏；不会要求每晚都必须有活动或机械填满每日上界。短活动与长活动、不同区域的转场、用餐休息和用户节奏必须放在一起判断。模型估算的停留时间和室内外判断作为参考，不冒充实地确认。

自动排程仍可修复实际交通导致的衔接偏差，记录移动或软休息调整；其保守调整策略不构成独立的最短游玩/用餐时长校验。模型可以自行提出更短或更长的活动与休息。真正的时间矛盾仍反馈主 Agent 或显示在预览中。

运行预算仍保留：每次主模型工具循环最多 4 个请求，剩余预算内最多 2 次输出纠正；地图调用、总运行时间和共享限流保持不变。不会通过无限重试或编造未确认地点取得“成功”。此前暂缓的自由自主补查也没有在本轮新增。

## 重访与兼容性

活动卡片按独立活动 ID 锁定或删除。同日同地点有多次到访时，旧自然语言编辑协议仅凭日期和地点不能可靠确定哪一次；此时明确提示使用对应活动卡片，不悄悄改错。跨日或无歧义的编辑继续沿用原流程。

旧确认版本不回写、不补造历史审核。旧分段输出与审核记录可以读取；重新生成/修改后采用当前政策。新增内容均在已有 JSON 快照中，无数据库结构迁移。

## 验证范围与限制

新回归证明：一天 13 个短活动、13 个必去/预约可完整保留；同一地点日夜重访有独立 ID 和正确的来路交通；时间意图及模型建议窗口不改写物理可行时刻；仅缺 10 分钟建议余量不阻止保存，真实赶不上仍报错；营业记录有无来源区别处理；休整日不强塞景点，但必去遗漏和酒店接驳缺失仍被发现；补齐晚间却损害全天体验的修改可以被整体评分拒绝。

本轮一次三日样例中，模型仍选择每天 3 项活动，程序全部保留，交通检查无硬错误；独立整体审核正常返回评分与建议。这个样例说明没有额外裁剪或强制增点，不证明三项就合适，也不证明约束放松后模型每次都会生成高质量计划。后续应通过完整旅行 Badcase 与评测校准模型判断，而非重新增加固定活动数规则。验证仅使用内存副本和忽略的 artifacts，未写入用户确认行程或 API 配置。

最终验证：后端回归 322 项通过，其中包含重复到访的精确卡片删除与自然语言新增回归；桌面与手机浏览器回归共 70 项通过，前端格式检查与生产构建通过。
