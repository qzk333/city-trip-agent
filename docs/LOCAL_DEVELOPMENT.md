# 本地运行与服务配置

本文保留安装、API 配置、地图、住宿、重规划和数据迁移的详细说明。项目介绍、整体架构与截图见 [README](../README.md)；当前约束策略以[约束政策](CONSTRAINT_POLICY.md)为准。

## 本地启动（Windows PowerShell）

需要 Node.js 22.12+ 或 24+、Python 3.12+。安装脚本支持通过 `-Python` 指定解释器，也会尝试当前桌面环境内置的 Python。

在仓库根目录执行：

```powershell
.\scripts\setup.ps1
.\scripts\dev.ps1
```

首次克隆请先完成安装，再执行开发启动脚本。页面为 [http://127.0.0.1:5173](http://127.0.0.1:5173)，接口文档为 [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)。

开发脚本在当前终端等待，按 Ctrl+C 关闭它启动的两个子进程；日志位于 `logs/`。如果端口被占用，先关闭已有服务。

也可以在两个终端分别启动：

```powershell
# 终端一，仓库根目录
& backend/.venv/Scripts/python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000

# 终端二
Set-Location frontend
npm run dev
```

## macOS / Linux 手动启动

在仓库根目录安装后端并迁移数据库：

```bash
python3 -m venv backend/.venv
backend/.venv/bin/python -m pip install -r backend/requirements.lock
backend/.venv/bin/python -m pip install --no-deps -e backend
backend/.venv/bin/python -m alembic -c backend/alembic.ini upgrade head
```

在前端目录安装依赖：

```bash
cd frontend
npm ci
```

随后在两个终端分别运行：

```bash
# 终端一：仓库根目录
backend/.venv/bin/python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

```bash
# 终端二：前端目录
npm run dev
```

以下 Windows 检查命令在 macOS / Linux 上执行时，将
`backend/.venv/Scripts/python.exe` 替换为 `backend/.venv/bin/python`。

## 体验路径

1. 保留默认地点，勾选固定预约，点击“生成我的行程”。
2. 查看时间轴、路线示意和行程检查，再保存演示行程。
3. 点击“晚出发 40 分钟”，检查预约是否保留、其余活动如何变化，确认更新。
4. 刷新页面继续查看，打开版本记录恢复历史安排。
5. 将结束时间改成 09:10 后生成新行程，观察无法满足条件时如何阻止保存。

## 目的地与用户 API 配置

目的地支持国家/地区 → 省份、州或行政区 → 城市三级下拉，并可在当前行政区检索中文或英文城市名。地理目录在本地提供，不需要地图 Key；切换城市会清空旧地点、预约与目录引用，并使用目的地当地时区。

下拉选项读取 `data/geography/` 的固定 JSON 数据并在后端内存缓存，不是在线搜索，也不保存在行程数据库。中国大陆使用中文地级行政区与四个直辖市目录（广东为 21 个地级市），不把区县、乡镇混入城市选项；暂未列出省直辖县级目的地。真实景点、交通和天气通过用户的高德 Key 在线查询。

点击页面右上角「API 设置」，填写自己的服务信息：

- 模型：选择使用模型，填写公开 HTTPS 服务地址、模型名称、API Key。程序追加 `/chat/completions`，服务需支持工具调用和 JSON 输出。
- 高德：填写 Web 服务 Key 后，在目的地下面点击「查询城市真实地点」，再选择想去的地方。加载的 POI 与这次旅行一同保存，后续调整使用同一目录。
- 浏览器地图：可选填单独的 JS API Key 与安全密钥；未填时保留路线示意。修改浏览器地图凭据后页面会刷新。
- 可分别测试模型和高德连接，按钮下方显示校验、进度和结果；超过 20 秒可见超时提示并恢复重试。模型连接测试只验证基础响应，工具兼容性在实际规划时检查；测试及规划会消耗用户自己的额度。

高德控制台的 Key 申请方式：

| 需要的功能 | 选择的服务平台 | 填入网页 |
| --- | --- | --- |
| 查询真实地点、路线、天气 | **Web服务** | 高德 Web 服务 Key |
| 显示网页交互地图（可选） | **Web端(JS API)** | 高德 JS API Key 和配套安全密钥 `securityJsCode` |

Web 服务使用一个 Key 调用地理编码、关键字搜索、路径规划（步行/公交）、天气查询、坐标转换、行政区域查询（连接测试）。不是每个 API 申请一个 Key；实际可调用能力和额度由高德账号的权限与配额决定，连接测试成功不代表所有接口均已验证。
官方说明：[Web 服务入门](https://lbs.amap.com/api/webservice/gettingstarted)、[JS API Key 与安全密钥](https://lbs.amap.com/api/javascript-api-v2/prerequisites)。

API 配置现在保存到项目目录的 **`.local/api-config.json`**，首次在网页保存时自动生成。重启后端、关闭浏览器或更换浏览器后都会重新读取这个文件；不依赖浏览器缓存。文件包含模型、地图模式以及模型 Key、高德 Web Key、JS Key 和安全密钥，均为明文，便于在本机查看与修改。手动编辑后刷新页面即可加载；空配置格式参考 [配置模板](../config/api-config.example.json)。

整个 `.local/` 目录及原子写入临时文件已被 Git 忽略，模板没有真实 Key。正常 `git add`、提交和推送不会包含本机配置，别人克隆仓库后自行填写。「清除已保存配置」会删除本地配置文件并回到演示模式。配置不写入行程、任务或数据库。

从旧版本升级时，页面会在本地文件尚不存在时自动迁移旧 `sessionStorage` / `localStorage` 的配置。文件保存成功后才清除旧缓存；迁移失败会保留原 Key 并在设置页面提供重试。已有本地文件优先，不被旧缓存覆盖。

配置文件的网页读写只允许本机访问，回复标记为 `Cache-Control: no-store`。普通本机请求由后端从文件读取模型和 Web 服务 Key；浏览器仅在内存中保留页面所需配置。**远程请求不会继承项目本地凭据，网页仍不继承 `.env` 中的 Key。** 原有环境凭据仅供明确执行的命令行工具验证。这是本地个人开发模式，公开多用户部署需要另行实现用户隔离。

模型自定义地址仅支持公开 HTTPS/443，不接受内网、账号或查询参数。服务端将校验后的公网 IP 用于连接，并保留原域名的 TLS SNI 与 Host，不跟随跳转。

DeepSeek 官方接口可填写 `https://api.deepseek.com`，模型名称按服务商实际支持的 ID 填写。应用会为该官方域名显式关闭思考模式，使其支持本项目首轮强制工具调用；连接测试使用同样的模式。依据是 [DeepSeek Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/) 中思考模式与 `tool_choice=required` 的限制。该适配不会自动修改用户选择的模型，也不会静默切回规则演示。规划错误会区分 HTTP 状态、输出截断、缺少工具调用、JSON 和地点 ID 校验失败；不回显上游可能包含 Key 的原始报错。

候选阶段优先一次查询完整地点目录；同一轮可以返回多个工具调用。程序按每个调用 ID 回复，对重复查询复用缓存。最多执行 6 次不同目录查询、请求模型 4 轮；目录已覆盖、预算用尽或模型只重复查询时，关闭后续工具调用并要求输出最终候选。超过执行预算的调用收到明确的预算回复，不再因为整批超过 3 个调用而直接失败。

地理目录覆盖全球国家/地区，但当前高德适配器接入的是中国大陆标准接口。境外可选择目的地并体验示意排程，真实地点、路线与天气暂不支持。杭州保留原演示夹具；其他城市未查询真实地图时使用明确标注的占位活动，不冒充景点。真实 POI 的营业、预约和建议停留时间仍需核实。

## 网上攻略、多日交通与地图

### 按旅行需求查找候选

在查询真实地点前填写「这次想怎么玩」：同行人、步行偏好、历史/夜景/摄影等主题与补充说明。系统将常见中文偏好和显式选项转换为有限查询，合并真实高德 POI，再综合匹配度、类型重复与距离排序；自由文本尚未实现通用语义澄清，复杂要求仍可能需要补充说明。

候选卡展示推荐理由、估算停留范围、地点来源及待核实信息。地图返回的名称/坐标与推测的主题、时长分开保存；不凭博物馆分类断言室内或适合老人，也不承诺景区内部少步行。日期、天数或偏好修改后会提示更新候选，已选的同城必去、预约和指定地点会保留。新接口为 `POST /api/places/recommendations`，旧查询接口继续兼容。

候选检索是程序生成的城市概览和偏好关键词，通过高德核对真实地点；模型不参与这一步查询。每条新候选保存命中的检索词、地图分类、来源与时间，查询顺序不冒充人气排名。

模型模式将最多 40 个已准入候选（优先保留保护项）交给主 Agent，比较城市代表性、兴趣和路线，返回选点、分天以及逐点理由。程序保留有效的模型分天，仅执行交通、时间与硬条件检查；不能排入的模型所选地点会阻止保存，不悄悄删除或用另一套分天顶替。模型仅返回排序时明确显示“模型排序、程序分天”。规则模式仍用每天约 8 个候选的短名单及空间分组，不保证全局最优。

行程展示主规划模型的实际请求次数、逐点建议与未排入候选的取舍；建议与地图事实分别标注。模型的城市代表性或地理解释属于判断，引用可解析不代表语义已核实。旧行程缺少这些记录时不会补造理由，重新生成预览后才会产生新说明。不会为全部候选请求真实的两两路线矩阵，地图调用继续经过同 Key 串行限流。

可离线比较候选排序与空间排程：

```powershell
& backend/.venv/Scripts/python.exe scripts/evaluate_quality.py
```

数据集含 30 条自建开发样例和合成地点/交通；输出位于被 Git 忽略的 `evals/results/travel-quality-v1.json`。该比较不代表真实旅游成功率，也不测量在线搜索召回率；原有 `scripts/evaluate.py` 继续验证基础排程冒烟任务。

网页默认「先规划路线，再选择酒店」。保存路线草案后，在路线下方按夜晚查看住宿候选：依据当日末站和次日首站展示位置、前后通勤距离估时、来源和查询时间。酒店 Agent 独立分析候选排序，住宿由用户选择；支持填写已订酒店的名称与坐标。选择后先补齐相邻两天的住宿交通；模型模式再由主 Agent 复核，必要时调整相邻两天内未锁定活动的顺序或日期，保留用户的酒店、抵离边界和锁定预约。模型复核失败会明确提示并保留程序计算的预览；冲突阻止确认。候选与选择随行程版本保存，可刷新、取消和恢复历史。

当前酒店来源为高德 POI，只提供位置参考，不接入房价、房型或库存；消费参考字段不会显示成房价。演示模式使用明确标注的示例位置。单日行程不自动安排过夜。已有固定住处可切换到「已有固定住处，每天往返」，旧行程仍按原模式解释。

生成前可勾选填写「抵达」「返程」地点与当地时间。通过地点搜索明确选择车站、机场或地址，也可手动确认名称与坐标。首日从抵达地点出发并预留出站时间，末日计算到返程地点的接驳及候车/值机余量；这些条件进入排程和独立校验。晚到、早走而没有游玩时间时，首末日可只安排接驳与休息，酒店候选相应参考抵达或返程地点。未填写时仍标明待确认。当前不查询火车/航班班次，也不处理跨夜接驳。

「计划变了？一起调整」支持自然语言。保存行程后，例如输入“把某个地点移到第三天，其他普通活动可以协调”“第三天去青羊宫，普通推荐可重新挑选”，先看修改预览，再确认保存。

普通修改先尝试最小变化；排不下时，把具体冲突、候选和硬约束交回主 Agent，最多进行 3 轮协调，可将其他普通活动移到空闲日期。用户明确指定的地点日期随需求版本保存，已选酒店、抵离时间、必去地点和锁定预约继续受保护。程序还提供经过路线与时间预检的有限跨日选项，模型不可用时可以用明确标注的程序可行方案兜底；没有可行方案则保留错误预览，阻止保存。单纯延迟复用原路线与休息空档。

「协调范围」支持按需求自动协调、只执行指定修改、允许全程协调。「允许重新挑选普通推荐地点」或自然语言中的重选要求，可允许替换普通推荐；未允许时保留原地点，仅协调日期和顺序。主 Agent 可按需补查景点，每次调整最多 2 次查询、每次最多 5 条，继续共用高德串行限流与缓存。新增地点必须来自 Provider，过滤交通站点、售票处等非景点结果；同名无法唯一确认时提示补充，不由模型编造坐标。

调整说明列出实际移动、新增、移除与时间变化，模型可补充原因；模型描述的地理解释仍需核实，不等于已验证的事实。演示模式仅支持有限语句和小规模规则协调，不联网补查。任意聊天、多轮澄清、自动获取预约/营业证明尚未实现。

启用模型或真实地图后，勾选「参考网上攻略」会检索当前城市和旅行天数对应的公开攻略，最多保留 6 个相关来源，并尝试读取其中最多 2 个公开 HTTPS 页面片段。页面标明「已读取页面片段」或「搜索摘要参考」，提供原文链接。检索失败会明确说明，继续按地点距离规划，不虚构联网来源。演示模式不执行联网检索。检索结果短期缓存，避免每次调整都重复搜索。

攻略 Agent 在独立上下文中分析检索证据，向主 Agent 提交带来源 ID 的结构化结论和待核实事项；主 Agent 结合结论、用户偏好与地点目录输出按天分组和交通建议。网页片段保留在攻略任务中，不放进主 Agent 消息。地点 ID 及来源 ID 均需通过校验；分析失败时记录降级原因，继续基础规划。攻略是参考资料，不能替代真实营业、预约、班次或价格核实。网页不会强制整趟旅行统一坐公交或全程步行，而是逐段建议步行、打车/自驾或公交，并结合高德估时。查不到某种路线时尝试合适的替代方式；暂时无法取得导航结果的路段明确标记「距离估时、待确认」，不冒充查到的导航路线。认证/权限、日额度和任务总预算问题仍会明确报错。

排程为后续日期保留候选，按请求天数分配活动，结合攻略分组与地理距离减少折返。可用地点或时间不足时仍会标明未完成。当前支持同一地点多次到访，按独立活动 ID 和逐次交通校验；是否重访由主 Agent 和审核 Agent 结合完整体验判断，详见[约束政策](CONSTRAINT_POLICY.md)。

地图卡片右上角「放大」打开大尺寸交互地图，保留缩放、拖拽和当天地点；支持关闭按钮及 Escape 收起。地点虚线仍是顺序示意，不是实际道路轨迹。

同一高德 Web Key 在当前服务进程内串行请求，默认间隔 1.05 秒；短期复用响应与路线缓存。HTTP 429 和 QPS 错误采用最多 2 次退避重试，日额度和权限错误不反复重试。间隔与预算可参考 `.env.example` 中的 `AMAP_MIN_INTERVAL_SECONDS`、`AMAP_MAX_RETRIES`、`MAX_RUN_SECONDS`，按控制台配额调整。首次生成可能需要几十秒；当前默认总预算为 120 秒。未来多进程/多实例部署需要共享限流器，当前不是分布式队列。

目录来源与数据许可见 [地理数据说明](../data/geography/ATTRIBUTION.md)，固定版本与转换脚本支持复现。境外目录仍可能包含城镇及部分区级地点，数据覆盖不等于地图服务覆盖。

命令行提供方检查仍可通过根目录 `.env` 显式配置后执行 `backend/.venv/Scripts/python.exe scripts/smoke_tools.py`；它与网页配置独立，未配置的提供方显示 `SKIPPED`。

## 数据库

默认数据库是 `data/local.sqlite3`，本地数据、密钥和原始评测输出不会提交。

迁移 `0004_requirement_snapshots` 为预览和历史版本增加需求快照：每日时段、抵离条件与行程一起确认、取消和恢复。旧记录按迁移时的旅行需求回填；过去未记录的需求变化无法追溯。本地 SQLite 启动自动升级；本轮升级前备份保存到被忽略的 `.local/backups/`。

迁移 `0005_catalog_snapshots` 为预览和版本增加地点目录快照：增量查询先属于未确认预览，确认时将需求、目录、行程一起原子保存；取消不会扩充当前旅行目录，恢复历史同时恢复对应地点证据。旧目录按迁移时的旅行目录回填。对于缺少 `place_days` 的旧行程，只从已确认且仍匹配当前日期的修改任务恢复地点日期要求，不跨越历史恢复边界推断。

安装脚本执行初始迁移。手动迁移命令：

```powershell
& backend/.venv/Scripts/python.exe -m alembic -c backend/alembic.ini upgrade head
```

保留 PostgreSQL 配置入口：在根目录 `.env` 设置 `DATABASE_URL=postgresql+psycopg://...`，再执行迁移。当前未验证真实 PostgreSQL 环境。
