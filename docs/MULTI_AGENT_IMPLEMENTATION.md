# 路线优先的多 Agent 实施记录

目标交互：系统提出有证据的候选，用户作出住宿决策，系统根据决策完成局部重规划。

## 第一步：独立攻略上下文与任务持久化（已实现）

- 图入口先运行攻略研究任务，再进入主 Agent 的候选选择、排程和程序校验。
- 攻略模块复用受限的公开搜索和页面读取。在取得来源后，使用独立的 system/user 消息完成一次结构化模型分析；不共享主 Agent 的消息历史，不负责选择酒店或生成每日路线。
- 攻略交付物包括摘要、带来源 ID 的结论、涉及的目录地点 ID、待核实事项。服务端拒绝无法解析的来源或地点引用，拒绝模型在分析阶段请求其他工具。
- 主 Agent 只接收结构化结论和被引用来源的链接、片段类型。原始搜索摘要、页面片段保留在攻略任务结果中，不放进主 Agent 的消息。现有网页仍可展示原始攻略来源。
- 主 Agent 保留目录工具调用、候选 ID 校验、多日分组、确定性排程与独立校验。行程调整继续使用已有的结构化交互和版本确认。
- 攻略最多新增一次模型请求，单次 HTTP 超时参数上限 15 秒，预留主规划时间。没有来源、模型不可用、时间不足或输出校验失败时，记录降级原因，主流程按目录继续；演示模式不额外请求模型。

### 数据与查询

迁移 `0003_agent_tasks` 新增 `agent_tasks` 表；本地 SQLite 启动自动升级，PostgreSQL 仍使用 Alembic CLI 显式迁移。

每条任务绑定 `run_id`，间接绑定旅行及该次运行的 `base_version`，保存角色、输入快照、执行状态、结构化结果和起止时间。角色目前为 `guide`、`main`、`hotel`；原始模型聊天记录和服务凭据不存入任务表。

- `GET /api/runs/{run_id}`：附带轻量的任务状态摘要。
- `GET /api/runs/{run_id}/agent-tasks`：查看任务输入、研究证据及结构化结果。
- 数据默认保存至 `data/local.sqlite3`，凭据仍单独保存在 Git 忽略的 `.local/api-config.json`。
- 后续主规划失败不会回滚已经完成的攻略任务；服务重启将未完成任务标为 `interrupted`，保留已完成结果。

### 当前边界

这是受控的三个角色协作流程，攻略 Agent 为“固定检索 + 单次独立模型分析”，酒店 Agent 为“按路线查询 Provider + 单次独立模型排序”；尚未实现由模型动态拆分任务、多轮自主搜索、自动恢复或跨运行复用研究。

引用检查验证 ID 可解析，不能证明每条模型结论均被来源内容支持。语义上的证据支持率需要后续评测。

固定住处模式继续兼容旧行程。网页新建默认使用路线优先模式，先生成不含未选酒店往返交通的草案，再调查住宿候选。

## 第二步：路线草案与酒店候选（已实现）

- `Requirements.lodging_mode` 支持 `route_first` 和兼容旧客户端的 `fixed`。网页默认前者；未选住宿前仅规划景点间路线，不强制返回城市参考中心。单日行程不自动添加过夜住宿。
- 酒店研究在路线草案之后执行。每晚读取当日末站和次日首站，分别在附近搜索，去重后保留最多 4 家；最多 2 晚，使用行程起止日期计算入住和退房日期。
- Provider 协议预留其他酒店来源；本轮实现高德酒店地点查询和明确标注的演示位置。高德请求复用同 Key 串行网关、间隔、缓存和有限重试，不为每家候选都请求导航。
- 候选包含位置、地址、来源链接、查询时间及前后两段的直线距离估时。高德 `cost` 字段不映射为指定日期房价，没有查询房型、库存、设施和取消政策，也未接入酒店报价沙箱。
- 酒店 Agent 用独立消息分析酒店证据和路线端点，仅返回各晚候选的排列。服务端检查候选集合完整、ID 归属和重复项；模型不选中酒店，不编造价格或资料字段。失败时保留按距离排列的 Provider 候选。
- 网页路线下方展示住宿候选，以夜晚标签切换。用户可以逐晚选择，也可以填写已订酒店的名称、坐标及坐标系；填写名称不会自动地理编码。同一酒店出现在多晚候选时提示可比较连续入住，不代表已确认有房。
- 证据查询及模型排序的输入、输出、状态保存在 `hotel` 任务中；候选与用户选择随 proposal / version 的 itinerary JSON 一起持久化，无需新增数据库表。

## 第三步：用户决策与局部重规划（住宿选择路径已实现）

- 保存路线草案后，通过 `POST /api/trips/{trip_id}/hotel-selections` 提交 `base_version`、`night` 和 `candidate_id`，或用 `custom_location` 代替候选 ID。
- 候选从该旅行、该版本、该晚的持久化快照解析，拒绝外来 ID 和过期版本。选择先生成预览，沿用幂等确认、取消和版本恢复；不直接覆盖已确认行程。
- 先对相邻两天增加或替换该晚住宿交通，复用未改变的其他住宿路段和景点间路段；不重新请求攻略和酒店研究。
- 模型模式额外请求一次主 Agent 复核：输入结构化路线、交通、冲突和用户选择，可以保持路线，或重排/跨日移动相邻两天内的未锁定活动。程序执行受限操作并再次独立校验。不能修改酒店、抵离条件、预约、锁定活动、必去要求或其他日期；无效建议或网络失败会标明复核不可用，并保留程序方案。演示模式明确显示未请求模型。
- 保留活动时长及锁定活动。必要时顺延未锁定活动；无法满足时间、预约或抵离约束时显示冲突，禁止确认。远距离酒店产生冲突预览，不写入无效跨日时间。
- 非相邻日期保持原样。已有延误等调整保留用户住宿选择。住宿决策在新的行程版本中保存，刷新后继续显示。

当前没有独立 Worker 的图挂起/恢复机制；跨用户等待通过已保存版本和后续新 run 衔接。通用依赖图重规划、行李寄存及实际入住退房耗时尚未完整建模。

### 抵离条件与自然语言修改（已实现）

- 抵达、返程对象包括用户确认的地点坐标、当地时间及缓冲分钟。首日不早于抵达+出站缓冲开始接驳，末日必须在返程时间-候车/值机缓冲前到达返程地点。高德关键字搜索提供候选，用户明确选择后生效；不推断真实班次。
- 晚到/早走时首末日可仅安排接驳和休息；酒店查询端点使用抵达/返程地点，选择住宿后补齐直达路线并检查当日时间边界。
- `POST /api/trips/{trip_id}/revisions` 接受 `base_version` 与自然语言 `message`。主 Agent 一次模型调用返回受限编辑契约，程序校验 ID、操作范围和用户保护条件，再对涉及日期排程。模型输入只含结构化状态和目录，不引入原始攻略页或酒店研究上下文。
- 支持目录地点增删/移动/重排、室内优先、每日时段、已有抵离时间修改。新抵离地点仍只接受已确认目录 ID；景点可在目标重规划中按需补查。自然语言自由表达需要模型模式，演示模式仅支持有限规则语句。
- 若重排后无法保留用户请求的活动，预览标为不完整并阻止确认；不能静默删除活动来制造成功。歧义要求和不支持操作提示补充说明，不部分执行。
- `0004_requirement_snapshots` 为 proposal/version 增加需求 JSON；需求与行程共用预览、确认 CAS 和版本恢复事务。历史记录回填迁移时的旅行需求，不能还原从前未记录的需求差异。
- 按用户最新取舍，酒店仅提供位置参考，不接入报价服务，也不新增报价 Key 配置。

## 第四步：恢复、复用与评测（待实现）

按需求版本和资料时效复用已完成研究，补持久化执行恢复、共享限流与失败重试。对比当前基线与角色隔离方案的证据支持率、约束满足率、Token、延迟和局部重规划影响范围。

## 增补：目标驱动的重规划（已实现）

自然语言入口先解析目标和范围，尝试最小修改。冲突或明确重选时，把错误、允许日期、指定地点日期、必保留集合、实际交通和候选摘要交回主 Agent，最多 3 轮，共用本次时间与路线预算。普通分组可跨日协调，明确日期和锁定预约不可偷偷修改。

程序最多尝试 4 个单地点跨日预检选项供模型参考，均经过排程和独立校验。模型拒绝或不合规时，可提供明确标注的程序可行预览；没有可行选项则保留失败状态，禁止确认。演示模式仅做最多 12 个小规模规则尝试，不冒充模型。

允许重选时可替换普通推荐；每次运行最多发起 2 次城市/周边景点查询，每次最多 5 条，失败也消耗预算，重复查询复用结果。须有高德 ID、有效坐标、来源和估算限制。具名新增未唯一匹配时停止；泛类新增必须实际加入此前未安排的候选。不查询房价。

地点日期保存在 `place_days`；`0005_catalog_snapshots` 保存 proposal/version 目录。需求、目录和行程共同确认、取消与恢复。任务结果记录每轮分组、失败原因、搜索证据、路线调用数，模型返回 usage 时记录 Token 和延迟；不保存原始对话或 Key。上下文仅含结构化状态和当前地点、最多 24 条其他候选，不引入攻略原始页面。

网页展示协调范围、推荐替换开关、指定日期和逐项变更说明。模型提出的地理理由未做逐句证据蕴含验证，程序独立校验地点 ID、日期、时间、预约、路线及酒店边界。

## 本轮验证

152 个后端测试、10 条固定冒烟任务和 36 条桌面/手机浏览器回归通过；文案收尾后 4 条新流程复验通过。本轮新增真实模型自然语言解析、酒店变更主 Agent 复核和高德车站搜索实测；模型验证使用演示路线与酒店，结果不代表全行程真实导航。旧库升级前备份，44 条旅行、23 条版本及其他旧列内容逐项对比未改变。详见 `../evals/reports/boundaries-natural-revisions-checks.md`。

此前酒店排序与查询已实测湛江两晚各 4 家高德候选；选择后两段住宿交通取得高德导航结果，第 3 天保持原样。该次输入路线的景点间交通为演示估时。详见 `../evals/reports/hotel-agent-checks.md`。
