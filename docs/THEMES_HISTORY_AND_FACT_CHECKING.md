# 统一主题、历史行程与事实核验设计

日期：2026-10-26。

## 本轮实现

旅行偏好只使用 `profile.themes`。前端取消重复的粗粒度 `interests` 选择，候选检索、排序、规则排程及攻略 Agent 输入统一读取主题。保留“人文展览”“城市漫步”作为同一个主题列表中的可选项，兼容原有选择；有具体历史、建筑等主题时跳过重复的宽泛检索。排序取匹配主题的最高相关性，不累加同义主题，也不受点击顺序影响。

旧请求仅在输入边界兼容 `interests`：已有非空 `profile.themes` 优先，否则将旧类别转换为同名主题。输出与新存储不再含该字段。迁移 0007 同步处理旅行、版本和预览的需求快照，保留地点、来源、版本号和时间。旧目录指纹包含已删除字段，迁移时失效该指纹，保留原查询证据；下次主动更新候选时生成新指纹。

首页增加“历史行程”：

- 只列出 `current_version > 0` 且具有对应确认版本的旅行，不列出未保存草案。
- 支持按城市查询、分页、打开和删除，列表中的日期与活动来自确认版本。
- 从历史打开只展示已保存行程；刷新后也不会自动混入未确认的调整。发起新调整后恢复正常任务预览流程。
- 删除须在页面明确确认，校验当前版本并拒绝删除仍在执行任务的行程。关联版本、运行、子任务、操作和预览在同一事务内删除，不影响其他旅行。
- 共享候选目录与独立备份保留；SQLite 删除释放的页可复用，文件大小不一定立即缩小，不自动执行全库压缩。

接口：`GET /api/trips?q=&offset=0&limit=12`、`DELETE /api/trips/{id}`，删除体为 `{"base_version": 1}`。旧的单旅行版本记录与恢复接口继续保留。

首次规划的自主补查本轮不增加。原有自然语言修改中的有限补查继续按原逻辑工作。酒店继续提供位置参考，不接入实时价格。

## 后续：事实核验 Agent（仅设计，未实现）

可以增加一个独立事实核验 Agent，核对**已进入路线草案的具体地点和游玩日期**，与负责行程经验、区域和交通建议的攻略 Agent 分工。重点是证据获取与有效性检查，不是增加一个角色提示词。

流程：路线草案 → 按 POI ID、日期和时区创建核验任务 → 检索及提取结构化证据 → 程序核对适用日期、来源与时间 → 独立校验器检查 → 主 Agent 对有依据的冲突做有限调整 → 用户确认。

建议输出：

| 字段 | 内容 |
| --- | --- |
| 地点身份 | 内部 place_id、高德 POI ID、名称、地址，避免同名场馆串用 |
| 适用条件 | 实际游玩日期、目的地时区、证据生效起止日 |
| 营业安排 | 开闭馆时间段、最后入场时间、每周闭馆日、节假日例外 |
| 预约 | 是否必须预约、官方预约入口、提前规则；不假设有票 |
| 证据 | 来源 URL、页面标题、原文摘录、抓取时间、页面发布日期（若有） |
| 状态 | verified / unknown / conflicting / stale；注明待确认事项 |

官网或官方公告优先；一般旅游攻略可提供检索线索，不直接升级为确定的营业事实。模型只提取有出处的信息。来源互相冲突、无法确认适用日期或检索失败时返回 unknown/conflicting，并向用户展示原因；不能以模型常识填补。

程序负责验证时间、闭馆日及最后入场冲突，主 Agent 据此选择换日、调整时间或替换普通景点。必须去和固定预约等硬约束不得悄悄删除；无法满足时给出明确选择。预约规则与实际可预约库存分开，尚未接入库存就不显示“可预约”。

将事实与来源按地点、适用日期独立存储，与完整网页文本分开。主 Agent 上下文只接收短事实摘要及证据 ID。缓存设置有效期，查询过程限定轮次、页面数、超时与并发；首轮只核验选中地点，避免为全部候选逐个调用模型或搜索。

实施顺序：先接一个稳定的检索/页面读取来源及事实表；再支持一种城市/场馆的营业与周闭馆核验；最后补节假日、预约及冲突重规划。验收至少覆盖普通开放、周闭馆、节假日例外、同名地点、来源冲突、网页不可用、过期证据和无票务接口八类情况。

## 验证入口

`backend/tests/test_themes_history.py` 覆盖单字段兼容、主题顺序、重复匹配、只列确认行程、筛选分页、删除隔离、版本冲突与执行中保护。`backend/tests/test_migrations.py` 覆盖旧快照与证据保留。`frontend/e2e/trip-history.spec.ts` 覆盖主题提交、历史恢复、预览隔离、刷新、删除确认和键盘操作，分别运行桌面与手机浏览器。

合成评测将旧类别移至独立的 `baseline_categories` 比较字段，实际请求只使用同名 `profile.themes` 和原备注；不使用相关性标签生成请求。当前共享排程器下，30 条开发样例符合预期通过/阻断结果，nDCG@6 为 0.9434（类别顺序）/0.9774（统一主题），估算交通为 2732/768 分钟。均为自建开发数据，不能视为线上召回、真实旅行时间或模型准确率。

最终检查：221 项后端测试、52 条桌面/手机浏览器回归、Ruff、前端格式与生产构建均通过，原 10 条冒烟任务通过。真实本地服务的历史列表显示 14 份已确认旅行，桌面与 390 像素宽手机视口无横向溢出；没有调用付费模型或地图来验证本轮管理功能。

本地迁移前备份至被 Git 忽略的 `.local/backups/local-before-themes-20261026-184205-902924.sqlite3`。迁移后逐表比对：53 trips、29 versions、59 proposals、72 runs、29 actions、41 agent_tasks、14 catalogs 均保留；仅转换 141 个需求快照和旧目录指纹，其他字段一致，SQLite 完整性检查通过，API 配置文件摘要不变。测试中的删除仅作用于独立测试库，未删除真实本地行程。
