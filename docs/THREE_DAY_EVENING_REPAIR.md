# 三日计划的晚间修复

> 历史实施记录：其中晚间优先、固定阈值和地点唯一等策略已调整，当前行为以[约束政策](CONSTRAINT_POLICY.md)为准。

2026-10-27。

## 本次原因

用户最近三日深圳草案结束上界为 23:00。第一版每天只选择约两个活动，第 1 天 15:15 后、第 3 天 15:45 后无具体安排。主 Agent 的第二次生成确实执行，但仍主要增加白天活动，并产生休息占用转场的问题；第二次审核又因日标签与问题分类未一一对应，被整份判为 `inconsistent_verdict`。更差的修改版被丢弃，保留原稿。

仅修复输出格式不够：需要让主 Agent 直接处理逐日时段缺口，修正软休息排程，并让审核报告的有效判断可以进入闭环。

## 改动

- 首次生成仍使用目录 Function Calling。审核后修改改为专门的时间表修复请求，复用现有候选、天气、逐日审核目标、地点使用清单和已查交通，不再重新调用目录工具。
- 修复输出采用 `RepairScheduledDay`：先写 `evening_activities` 与 `evening_explanation`，再分配 `daytime_activities`、用餐休息与天气取舍。先为多天比较不重复的晚间地点，再分配其余白天候选，避免只增加下午的场馆。旧的普通推荐可以移动或替换，用户必去、指定日期和预约仍受保护。
- 分段输出经统一解析转为原有 `ScheduledDay`，继续查真实交通、校验全程唯一与硬约束。日间/夜间选择同一地点仍会反馈纠正，不通过重复地点填满时段。
- 晚间优先比较街区、滨水和平缓户外空间。没有夜场依据的博物馆/展馆建议留在白天；开放、照明、内部步行仍标为待核实。晚间列表可为空，但必须解释实际限制，独立审核判断合理性，不要求机械排到 23:00。
- 审核报告的逐日 `missing`、`too_sparse` 等标签已经是模型判断。若缺少一条冗余的同分类问题行，保留该判断并从模型的逐日解释生成结构化反馈，不再整份拒绝。未知地点、跨日错误引用、日期覆盖和格式仍验证。
- 修复软休息回填的触发条件：除了活动/休息重叠，也检查交通与休息的合计是否超过空档。最短 15 分钟的可调整休息无法放入时，重新定位到实际空档或合并，不任由 1 分钟的转场不足淘汰整版。用餐不直接删除，固定预约不移动，没有可行空间仍保留具体错误。
- 选版先比较硬冲突与晚间目标，再比较体验审核可用性和其他问题。二次审核不可用时，无硬冲突且实际减少晚间遗漏的修改版可保留，仍明确展示“体验审核未完成”；不会将未完成审核说成通过。
- 未选择主题时，初始候选检索增加特色街区、步行街和博物馆渠道，沿用最多六个主查询与两个不足补查的预算。已有目录需要通过“更新候选”才取得新增渠道；规划过程中没有新增自由无限补查。
